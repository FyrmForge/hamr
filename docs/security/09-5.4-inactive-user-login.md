# 09 — `users.active` not checked in Authenticate

**CVSS:** 5.4 (Medium) — `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:L/A:N`

**Where:**
- `internal/cli/generator/templates/new/internal/service/auth.go.tmpl:65-83` — `Authenticate` fetches user, checks password, returns user. No check on `user.Active`.
- `internal/cli/generator/templates/new/internal/db/migrations/001_initial.up.sql.tmpl:23` — `active BOOLEAN NOT NULL DEFAULT true` in schema.

## What's wrong

The schema ships an `active` column with implied semantics ("deactivated users can't log in"), but the only auth path in the scaffold ignores it. A user flagged `active = false` continues to authenticate normally.

## Exploit

An operator deactivates a compromised account (via DB update or admin tool). The original credential continues to work because the login flow never reads `active`. Same problem applies to soft-deletion patterns built on top.

## Fix

After `CheckPassword` succeeds, return `ErrInvalidCredentials` (not a distinct "inactive" error — that's a separate user-enumeration leak) if `!user.Active`. Mirror the check in any other auth entry points (password reset, API token issuance) the dev adds later.

Worth a framework-level note: the scaffold should either own the active check or stop shipping the `active` column.
