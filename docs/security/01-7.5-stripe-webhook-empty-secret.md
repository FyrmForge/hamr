# 01 — Stripe webhook secret defaults to empty

**CVSS:** 7.5 (High) — `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:H/A:N`

**Where:**
- `internal/cli/generator/templates/new/cmd/site/main.go.tmpl:95` — `envStripeWebhookSecret = config.GetEnvOrDefault("STRIPE_WEBHOOK_SECRET", "")`
- `internal/cli/generator/templates/new/internal/api/server.go.tmpl:31` — handler registered unconditionally
- `internal/cli/generator/templates/new/internal/api/handler/stripe/handler.go.tmpl:75` — `webhook.ConstructEvent(payload, sig, h.webhookSecret)`

## What's wrong

The scaffolded Stripe webhook handler is wired up even when `STRIPE_WEBHOOK_SECRET` is unset (it falls back to `""`). `webhook.ConstructEvent` will still attempt HMAC verification against the empty key — and an HMAC over a known empty key is computable by anyone.

## Exploit

Attacker POSTs to `/api/webhooks/stripe` with a payload and a `Stripe-Signature` header generated using HMAC-SHA256 with key `""`. Library accepts it as authentic. Any business logic wired into the handlers (order completion, refund processing, subscription state) can be triggered without involving Stripe at all.

## Fix

Fail startup when the route is registered and the secret is empty (or in dev mode only, log loudly and refuse to register the route). Don't accept `""` as a valid signing key anywhere in the call chain.
