# Templates and htmx

HAMR renders HTML with templ, which compiles templates to type-safe Go, and adds interactivity with htmx so pages stay server-driven without client-side JavaScript. Alpine.js is an opt-in for local UI state.

**Package references:** [HTMX](pkg/htmx.md), [Respond](pkg/respond.md)

## Templ components

[Templ](https://templ.guide/) gives you compile-time type safety, autocompletion, and prevents runtime template errors. Each page package keeps its `.templ` files next to `handler.go`, in the same Go package, with unexported components:

```text
internal/web/handler/home/
├── handler.go       // package home
├── home.templ       // templ homePage(c echo.Context)
└── home_templ.go    // generated by `templ generate`
```

Shared pieces live in `internal/web/components/`: `Layout`, `ErrorPage`, `StaticURL`, `GetUser`, and form helpers under `components/form`.

### Rendering

Use `respond.HTML` to render a component:

```go title="internal/web/handler/home/handler.go"
// GET /
func (h *handler) Index(c echo.Context) error {
    return respond.HTML(c, http.StatusOK, homePage(c))
}
```

### Layout pattern

Pages wrap their content in `components.Layout(c echo.Context, title string)`:

```templ title="internal/web/handler/home/home.templ"
package home

import (
    "github.com/labstack/echo/v4"
    "github.com/user/myapp/internal/web/components"
)

templ homePage(c echo.Context) {
    @components.Layout(c, "Home") {
        <main class="container">
            if user := components.GetUser(c); user != nil {
                <h1>Welcome, { user.Name }</h1>
            } else {
                <h1>Welcome</h1>
            }
        </main>
    }
}
```

The layout (`internal/web/components/layout.templ`) takes the Echo context so it can render the flash message. Trimmed:

```templ title="internal/web/components/layout.templ"
templ Layout(c echo.Context, title string) {
    <!DOCTYPE html>
    <html lang="en">
    <head>
        <title>{ title } - myapp</title>
        <link rel="stylesheet" href={ StaticURL("css/base/variables.css") }/>
        // ... one <link> per stylesheet under frontend/static/css/
    </head>
    <body>
        if flash := middleware.GetFlash(c); flash != nil {
            <div class={ "alert", FlashAlertClass(flash.Type) }>{ flash.Message }</div>
        }
        { children... }
        <script src={ StaticURL("js/htmx.min.js") }></script>
        <script src={ StaticURL("js/main.js") }></script>
        <script>/* htmx setup, see below */</script>
    </body>
    </html>
}
```

`ErrorPage` calls `Layout(nil, ...)` because error pages have no request to pass down; the flash lookup tolerates a nil context.

## HTMX

HAMR is HTMX-first: the server sends HTML fragments and HTMX swaps them into the DOM. The `htmx` package provides request detection and response header helpers.

### HTMX setup in the layout

The scaffold's layout ends with an inline script. Both parts are required; keep them when you edit the layout.

```html title="internal/web/components/layout.templ"
<script>
    htmx.config.responseHandling = [
        {code:"204", swap: false},
        {code:"[23]..", swap: true},
        {code:"400", swap: true, error: false},
        {code:"422", swap: true, error: false},
        {code:"429", swap: true, error: false},
        {code:"[45]..", swap: false, error: true}
    ];
    document.addEventListener('htmx:configRequest', function(evt) {
        var csrfToken = document.querySelector('input[name="csrf_token"]');
        if (csrfToken) evt.detail.headers['X-CSRF-Token'] = csrfToken.value;
    });
</script>
```

- **`responseHandling`** — htmx 2 does not swap 4xx responses by default. Handlers return invalid forms as `422` (`respond.HTML(c, http.StatusUnprocessableEntity, ...)`), so without this block form errors never render. Only the codes listed with `swap: true` are swapped; if you re-render a form with another status, add it here.
- **`htmx:configRequest`** — copies the CSRF token into an `X-CSRF-Token` header on every HTMX request. Without it, HTMX requests that don't carry a form containing the token (e.g. `hx-post` or `hx-delete` on an element outside a form) fail CSRF. The token is read from the first `<input name="csrf_token">` on the page, rendered by `@form.CSRFField(c)`, so a page that makes HTMX `POST`s needs at least one.

The site CSP allows `'unsafe-inline'` scripts for this block (see [Routing and handlers](routing.md#route-groups)). `frontend/static/js/main.js` holds the remaining HTMX event handlers (error logging, scroll-to-error, re-validation).

### Partial vs full rendering

```go
func (h *handler) List(c echo.Context) error {
    users, err := h.users.List(c.Request().Context())
    if err != nil {
        return err
    }

    r := c.Request()
    if htmx.IsHTMX(r) && !htmx.IsBoosted(r) {
        // HTMX request: render just the partial
        return respond.HTML(c, http.StatusOK, userTable(users))
    }
    // Full page or hx-boost navigation: render with layout
    return respond.HTML(c, http.StatusOK, userListPage(c, users))
}
```

`IsHTMX` is true for every request htmx makes, including `hx-boost` navigations, which expect a full page. Exclude them with `IsBoosted`, or use `htmx.GetTarget(r)` (the `HX-Target` id) when one endpoint serves several targets.

### Redirects

Use `respond.Redirect` in handlers. It sends `HX-Redirect` for HTMX requests and a 303 otherwise:

```go
return respond.Redirect(c, "/dashboard")
```

To set only the header, call `htmx.Redirect(c.Response(), "/dashboard")`.

### Triggering events

Fire custom events on the client:

```go
htmx.Trigger(c.Response(), "userCreated", "showToast")
htmx.TriggerAfterSettle(c.Response(), "formReset")
```

### Swap control

Override the swap strategy or target:

```go
htmx.Reswap(c.Response(), "outerHTML")
htmx.Retarget(c.Response(), "#error-container")
```

### URL manipulation

Update the browser URL bar:

```go
htmx.PushURL(c.Response(), "/users/42")
htmx.ReplaceURL(c.Response(), "/users/42")
```

## Alpine.js (optional)

Alpine.js is opt-in. Enable it at scaffold time via `hamr new --alpine` (or answer **yes** to the Alpine prompt in the wizard). To add Alpine to an existing project, run `hamr vendor alpine` and add `<script src={ StaticURL("js/alpine.min.js") } defer></script>` to the layout's `<head>`. Use it for dropdowns, modals, tabs, and other local UI state:

```html
<div x-data="{ open: false }">
    <button @click="open = !open">Toggle</button>
    <div x-show="open" x-transition>
        Dropdown content
    </div>
</div>
```

Alpine works alongside HTMX — use HTMX for server communication, Alpine for client-side UI state.

## The StaticURL helper

Reference assets with `StaticURL` (in `internal/web/components/helpers.go`) instead of hardcoded paths. Inside `package components` call it directly; from page packages use `components.StaticURL`:

```templ
<link rel="stylesheet" href={ StaticURL("css/base/reset.css") }/>
<script src={ StaticURL("js/htmx.min.js") }></script>
```

`hamr gen static` copies `frontend/static/` into `frontend/dist/` with content-hashed filenames and writes the mapping to `components.StaticManifest` (`staticmanifest.go`, generated). `StaticURL` returns the fingerprinted path when the asset is in the manifest and the plain path otherwise. `hamr dev` runs `hamr gen static` whenever a static file changes, and `make build` runs it before compiling.

The prefix comes from `STATIC_BASE_URL` (default `/static`). In production, point it at the CDN origin that serves the synced `frontend/dist`:

```env
STATIC_BASE_URL=https://cdn.example.com
```

See [Static assets → CDN patterns](static-assets.md#cdn-patterns).

## Vendored JS

htmx and idiomorph are vendored into `frontend/static/js/` (plus Alpine.js when you opt in); the scaffold layout loads only htmx, so add an idiomorph `<script>` if you use morph swaps. Manage versions with `hamr vendor` — see [Static assets](static-assets.md#js-vendoring).
