# 08 — Symlink escape in static file serving

**CVSS:** 5.5 (Medium) — `CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N`

**Where:**
- `pkg/server/server.go:122-135` — `e.StaticFS("/static", newLayeredFS(os.DirFS(s.staticDistDir), os.DirFS(s.staticDir)))` and `e.StaticFS(s.embeddedPrefix, s.embeddedFS)`
- `pkg/server/layeredfs.go:17-22` — passes lookups through verbatim

## What's wrong

`os.DirFS` is documented by Go as **not** a security boundary — it does not block symlinks pointing outside the root. Whatever Echo's `StaticFS` opens via that FS will follow links.

## Exploit

Pre-conditions: attacker can place a symlink under the configured `static/` or `dist/` directory. Realistic paths:
- CI artefact upload that includes a tarball with embedded symlinks.
- A separate file-write bug in the app that writes into `static/`.
- A misconfigured deploy that mounts user-uploaded content under `static/`.

Once a symlink exists, anyone can `GET /static/<link>/<rel>` and read host files the app has access to (config, keys, `/etc/passwd`).

## Fix

Wrap the FS with a confinement layer that calls `filepath.EvalSymlinks` and verifies containment, or refuse to serve any path whose `Lstat().Mode()` contains `fs.ModeSymlink`. Long-term, switch to `os.OpenInRoot` once the Go floor allows.
