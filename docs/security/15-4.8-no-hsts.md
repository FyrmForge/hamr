# 15 — No HSTS support in secure middleware

**CVSS:** 4.8 (Medium) — `CVSS:3.1/AV:A/AC:L/PR:N/UI:R/S:U/C:L/I:L/A:N`

**Where:**
- `pkg/middleware/secure.go:10-48` — `SecureConfig` only exposes CSP, XFO, Referrer-Policy, X-XSS, ContentTypeNosniff. No `StrictTransportSecurity` field. The underlying `echo/middleware.SecureConfig` supports it, HAMR's wrapper drops it.

## What's wrong

The "secure headers" middleware can't emit `Strict-Transport-Security`. For an HTTPS site, HSTS is the single most important header here — it's what stops an on-path attacker from downgrading a user's first visit. HAMR's wrapper provides no way to set it short of bypassing the wrapper and wiring `echo/middleware.Secure` directly.

## Exploit

User on a hostile network types `example.com` into the address bar. Without HSTS:
- Browser issues plaintext HTTP request to port 80.
- Attacker intercepts, returns a phishing page or proxies the real site while harvesting credentials.
HSTS preload (browser-shipped list) or a prior visit with the header would block this; HAMR can't help with either.

## Fix

Add `StrictTransportSecurity string` to `SecureConfig`, forward to the Echo middleware. Default to `max-age=31536000; includeSubDomains` when `!devMode`. Document `preload` as an opt-in for projects that own their apex.
